SAKAN
Implementation-Ready Project Structure & File Responsibilities
Technical Engineering Specification — Version 1.1

1. Purpose
This section converts the Sakan product specification into an implementation-ready software structure.
The objective is to define:
The exact project folder structure.
The responsibility of each folder.
The responsibility of each important file.
The API structure.
The database and Supabase structure.
Authentication and authorization boundaries.
Shared services and business logic.
Testing structure.
Production and deployment structure.
The development team or AI coding platform must use this structure as the engineering blueprint.
The project must be implemented as a real production-oriented full-stack application, not as a static prototype or simulated demo.

2. Recommended Technology Structure
The project uses:
Next.js
TypeScript
React
Tailwind CSS
Supabase
PostgreSQL
Supabase Auth
Supabase Storage
Supabase Realtime
Stripe
AI Services
Vercel
PWA

The application uses the Next.js App Router.

51. RLS Requirements
Supabase Row Level Security must be enabled for all user-sensitive tables.
Examples:
Users can read their own private data.
Users can update their own profile.
Users cannot update another user's profile.
Conversation members can read their conversations.
Conversation members can send messages where permitted.
Users cannot read another user's private payment information.
Users cannot access admin data.
Admins receive access only according to their assigned role.

RLS must remain active even if an API endpoint contains an implementation mistake.
